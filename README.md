# 開拓の島 モフルジム

島に道とジムを建てて、モンスター「モフル」を進化させ、ジムバトルで競うボードゲームです。スマホのブラウザでそのまま遊べます。

**遊ぶ：** https://tm550120.github.io/mofuru-gym/

**はじめての人へ（チュートリアル）：** タイトルの「📖 はじめての人へ」を押すと、本物のゲーム画面で案内（吹き出し）どおりにタップしながら、初期配置・建設・進化・交換・7とジムバトルまでをひととおり練習できます（島・サイコロの目・CPU の動きは練習用に固定。保存データや設定は変わりません）。

**遊び方・早見表（読み物）：** https://tm550120.github.io/mofuru-gym/tutorial.html （操作の手順・勝ち方のコツ・早見表を 1 ページにまとめたもの。タイトルの「遊び方・早見表」、チュートリアルのしめくくり、ゲーム中の「?」の遊び方から開けます）

## 遊び方（モード）

URL を開くとタイトル画面が出るので、モードを選びます。ゲーム中は右上の「⌂」でタイトルに戻れます。

**ブラウザの「戻る」はタイトル（ホーム）に戻ります：** チュートリアル・対戦・CPU 設定・オンラインの画面でブラウザの「戻る」を押すと、前に見ていた別のページへは出ていかず、タイトルのメニューに戻ります。対戦中・チュートリアル中は「⌂」と同じ確認が出ます（取り消せばそのまま続けられます。CPU 対戦は保存されて「続きから」再開でき、オンライン対戦は「⌂」と同じく対戦から抜けます）。読み物ページ・管理ページの「戻る」リンクは履歴に積まないので、タイトルで「戻る」を押してもそれらのページには戻りません。

- **CPUと対戦**：あなた＋CPU 2人で遊びます。始める前に、あなたの手番（先攻・2番目・3番目・ランダム）と進行スピード（ゆっくり・ふつう・はやい）を選べます。
  - ゲームの状態は操作のたびに端末（localStorage）へ保存されます。リロードしたりタイトルに戻ったりしても、タイトルの「▶ 続きから」で同じ盤面・同じ状態から再開できます（リロードで盤面やサイコロを引き直すことはできません）。「新しいゲームを始める」を選ぶと保存は破棄されます。
- **フレンド対戦（オンライン）**：2〜3人で遊びます。
  1. ニックネームを入れて「部屋を作ってフレンドを招待」を押すと、5文字の部屋コードと招待リンクが出ます。
  2. フレンドはリンクを開くか、コードを入力して「参加する」を押します。
  3. 全員そろったらホストが「ゲーム開始」。「空いた席をCPUで埋める」をオンにすると、2人でもCPUを入れて3人で遊べます。手番は「ランダム」か「リストの順番」（▲で並べ替え）をホストが選びます。
  - 通信は PeerJS（WebRTC）でブラウザ同士を直接つなぎます（接続の仲介に PeerJS の無料公開サーバーを使用）。ゲームの進行はホストの端末が管理します。
  - ゲストの接続が切れたりリロードしたりしても、同じ端末ならタイトルの「▶ オンライン対戦に戻る」（または自動再接続）で自分の席に戻れます。しばらく戻らないときは、ホストが「CPUに交代」か「ゲームを終了」を選べます。
  - ホストの端末も状態を保存します。ホストがリロードした場合は、タイトルの「▶ オンライン対戦を再開（ホスト）」で同じ部屋コード・同じ盤面のまま部屋を開き直し、ゲストは自動で再接続します（約2分以内）。
  - 制限：部屋コードの取り戻しは PeerJS サーバーの都合で失敗することがあります（前の接続が残っている間は最大1分ほど再試行）。ゲストの再接続は同じブラウザ（保存されたトークン）でのみ可能で、新しい人の途中参加はできません。ネットワーク環境によってはつながらないことがあります。

## ルールの概要

- サイコロの合計と同じ数字の土地に接するジムは資源を1枚、都市は2枚もらえます。
- 資源を使って道・ジム・都市を建てます。盤面に置いておけるのは1人あたりジム5個・都市4個まで（初期配置の2個も数えます。ジムを都市にするとジムの枠が1つ空きます）。道は何本でも建てられます。
- 同じ資源3枚で、モフルが5つのタイプ（草・炎・風・光・岩）のどれかに進化します。
- 自分の番に「交換」から、銀行と4:1で交換するか、ほかのプレイヤーに交換を提案できます（1人または全員に提案し、最初に受けた人と成立）。CPUも損得を考えて受けたり断ったりし、ときどきCPUから提案してくることもあります。
- 7が出たら、手札が8枚以上の人は半分（切り捨て）を自分で選んで捨てます（全員が選び終わるまで待ちます）。出した人が進化済みなら相手のジムにバトルを挑めます。
- バトルはサイコロ1個＋ボーナス（進化+2、相性有利+1、都市ジム+1）。勝つと相手の資源を1枚奪い、バッジを1個もらいます。負けると進化前に戻ります。
- バッジを最初に3個集めた人がチャンピオン（+2点）。より多く集めた人が現れると移ります。
- 最長の道：自分のジム（都市）から別の自分のジム（都市）まで、自分の道だけで途切れずにつながった道が5本以上あれば対象になり、いちばん長い人が+2点（同じ長さなら先に取った人のまま）。途中に相手の建物があると途切れます。
- ジム1点、都市2点、最長の道2点、チャンピオン2点。先に10点で勝ち。
- CPUの動き・サイコロ・手番の交代は少し間を置いて表示され、直前の出来事が画面上部に表示されます（下の出来事欄をタップすると履歴）。スピードは「?」から変更できます。

タイプ相性：風 → 炎 → 草 → 岩 → 光 → 風（左が右に強い）

## 効果音・BGM

音はすべて Web Audio API で合成しており、音声ファイルは使いません。最初に画面をタップ（クリック・キー操作）したあとから鳴ります（自動再生はしません。それまでは音の準備（AudioContext）もしません）。音が出せないブラウザでは鳴らさずにそのまま遊べます。設定は端末に保存されます。

- **効果音**：ジムバトルで効果音が鳴ります（バトル開始・サイコロ・勝ち／負け。自分が関わらないバトルは短いチャイム）。
  - 初期値はオン。ゲーム中の右上の 🔊／🔇 ボタン、またはタイトルの「CPUと対戦」画面・ゲーム中の「?」の遊び方画面の「効果音（バトル）」で切り替えられます。
- **BGM**：場面ごとにループする BGM が流れます（オリジナル曲。チップチューン風：矩形波・三角波・ノイズ）。
  - タイトル（ロビー含む）：ゆったりした曲（84 BPM・約23秒でループ）
  - ゲーム中：明るい中くらいの速さの曲（112 BPM・約17秒でループ）
  - ジムバトル：速くて緊張感のある曲（150 BPM・約19秒でループ）。バトル演出のあいだ流れ、閉じるとゲーム中の曲に戻ります。効果音が鳴るあいだは BGM を小さくします
  - ゲーム終了（結果表示）はゲーム中の曲をそのまま流します。⌂ でタイトルに戻るとタイトルの曲になります。曲の切り替えは短いクロスフェードです
  - 音量は効果音より小さめです。タブを隠すと止まり、戻ると今の場面の曲を最初から流します
  - 初期値はオン。ゲーム中の右上の 🎵 ボタン（オフのときは薄く表示）、またはタイトルの「CPUと対戦」画面・ゲーム中の「?」の遊び方画面の「BGM」で切り替えられます（効果音のオン／オフとは別）。

## 管理ページ（試験機能）

`admin.html`（GitHub Pages なら `https://<user>.github.io/mofuru-gym/admin.html`、ローカルなら http://localhost:5173/admin.html ）は、開発者が試験中の機能を試すためのページです。タイトルのメニューのいちばん下にある「管理ページ（開発者用）」から開けます（一般のプレイヤーにも見えるので控えめな表示。中身はアクセスキーが必要）。

- 上の「← ホームに戻る」で、いつでも（アクセスキーを入れる前でも）タイトルに戻れます。
- アクセスキーを入れると開きます（開いた状態はブラウザのタブを閉じるまで有効）。**ブラウザ内だけの簡易ロックで、本当のセキュリティではありません**（静的サイトなのでソースを読めば回避できます）。見られて困る情報や操作は置かないでください。
- **バージョン**：ビルドしたコミット（短い SHA）とビルド日時。
- **リリースノート**：マージした PR ごとの、遊ぶ人から見た変更点（1 PR = 1 カード、新しい順。最初はすべて閉じていて「#番号・日付・見出し」だけ。タップしたカードだけ開き、ほかは閉じる）。リリースのたびに `frontend/src/admin/releaseNotes.ts` の `RELEASES` の先頭へ 1 件足します（マージ前の変更は `date`・`pr` を `null` にしておくと「次のリリース（日付・PR 未定）」と表示されるので、マージしたら埋めます）。
- **試験機能**：機能ごとにオン／オフ。**この端末（ブラウザ）だけ**に保存され、初期値はすべてオフです。一般のプレイヤーには試験機能は出ません。「ゲームを開く」でそのままゲームを確認できます。**いまは試験中の機能はありません**（効果音・BGM は正式公開済み。仕組みは今後の試験のために残しています。一覧は `frontend/src/features.ts` の `FEATURES`）。
- **効果音テスト**：開始・サイコロ・勝ち・負け・観戦の音を個別に再生（ゲームの効果音オン／オフ設定に関係なく鳴ります）。
- **BGMテスト**：タイトル・ゲーム・バトルの曲を再生／停止（ゲームの BGM オン／オフ設定に関係なく流れます。ページを開いただけでは流れません）。
- **演出テスト**：ダミーの盤面で実際のジムバトル演出（勝ち・負け・観戦）を再生。
- **データ**：保存データ（続きから）の削除、設定の初期化（ページ内で確認してから実行）。

### バックエンド（任意）

フロントエンドはバックエンドなしでも完全に動きます（CPU 対戦はオフラインで、オンライン対戦は PeerJS で）。バックエンドの役割は次のとおりです。

| メソッド / パス | 内容 |
| --- | --- |
| `GET /api/health` | `{ "status": "ok", "rooms": 登録中の部屋数 }` |
| `POST /api/rooms` | `{ code, peerId }` を登録（有効期限つき、既定2時間）。`201` で `hostToken` を返す。不正な値は `400`、登録済みは `409` |
| `GET /api/rooms/:code` | 部屋コードからホストの PeerJS ID を返す。無ければ `404` |
| `DELETE /api/rooms/:code` | `x-host-token` ヘッダーが正しければ削除（`204`）。違えば `403` |
| それ以外 | `frontend/dist` があれば静的ファイルとして配信 |

部屋コードの登録簿はメモリ上だけにあり、再起動で消えます。フロントエンドは `VITE_ROOM_API_BASE` が設定されているときだけ API を使い、ホストは部屋を作ったときに登録・閉じたときに削除、ゲストは参加時にコードを引きます。API に届かない・見つからないときは、従来どおり PeerJS ID（`mofuru-gym-<コード>`）で直接つなぎます。

環境変数：`PORT`（既定 8787）、`HOST`（既定 127.0.0.1）、`STATIC_DIR`（既定 `frontend/dist`、空文字で配信しない）、`ROOM_TTL_MS`、`CORS_ORIGIN`（別オリジンから API を呼ぶとき）。

## ローカルで動かす

Node.js 20.19 以上が必要です。

```sh
npm install
npm run dev        # バックエンド(:8787) とフロントエンド(:5173) を同時に起動
```

http://localhost:5173/ を開きます。開発時は `/api` がバックエンドに中継されます（`frontend/.env.development`）。フロントエンドだけ動かすなら `npm run dev -w frontend` です。

その他のコマンド：

```sh
npm run build      # frontend/dist と backend/dist を作る
npm test           # Vitest（ゲームロジックとバックエンド API）
npm run typecheck  # 全パッケージの型チェック
npm start          # ビルド済みのバックエンドを起動（frontend/dist も配信）
npm run preview -w frontend   # ビルドしたフロントエンドだけを確認
```

同じオリジンでバックエンドから配信し、部屋コード API も使う場合は `VITE_ROOM_API_BASE=/api npm run build` でビルドしてから `npm start` します。

## GitHub Pages へのデプロイ

`main` に push すると `.github/workflows/pages.yml` が型チェック・テスト・`frontend` のビルドを行い、`frontend/dist` を GitHub Pages に公開します。ビルドは相対パス（Vite の `base: './'`）なので `/mofuru-gym/` 配下でもそのまま動きます。

初回だけ、リポジトリの Settings → Pages → Build and deployment の Source を「GitHub Actions」に切り替えてください（これまでのブランチ直下の `index.html` はもうありません）。
